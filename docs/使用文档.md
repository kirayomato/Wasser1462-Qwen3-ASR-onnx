# Qwen3-ASR-onnx 使用文档

把 QwenLM/Qwen3-ASR 语音识别模型导出为 ONNX，用 ONNX Runtime 做离线批量推理和流式实时识别。推理端不需要 PyTorch。

- 上游模型与部分代码来源：<https://github.com/QwenLM/Qwen3-ASR>
- C++ 部署参考（sherpa-onnx）：`git clone -b feature/qwen3-asr-onnx --single-branch https://github.com/Wasser1462/sherpa-onnx.git`

---

## 1. 原理与产物

模型拆成三个 ONNX：

| 文件 | 作用 |
|---|---|
| `conv_frontend.onnx` | 音频特征卷积前端（mel → 卷积下采样输出） |
| `encoder.onnx` | 音频编码器主体 |
| `decoder.onnx` | 文本解码器，带 KV cache 自回归生成 |

每个都有 FP32 版（`encoder.onnx` + 外置权重 `encoder.onnx.data`）和 INT8 量化版（`encoder.int8.onnx`，单文件）。

## 2. 目录结构

```
.
├── export_qwen3_asr_onnx.py   # 导出脚本
├── run.sh                     # 导出一键脚本
├── infer_qwen3_asr.py         # 离线推理脚本
├── decode.sh                  # 离线推理演示（多种精度组合）
├── qwen3_asr.py               # Qwen3-ASR 的 config/processor 注册（transformers）
├── conv_frontend.py           # 导出用的 conv 前端包装
├── encoder.py / decoder.py    # 导出用的 encoder/decoder 包装
├── Qwen3-ASR-0.6B/            # HF checkpoint（config/tokenizer/safetensors）
├── model/                     # ONNX 产物（.gitignore 不入库）
├── test_wavs/                 # 测试音频（含参考文本表）
└── streaming_qwen3_asr/       # 流式识别：WebSocket 服务 + 浏览器页面
    ├── realtime_ws_server.py
    ├── streaming_qwen3_asr.py # 流式识别核心类
    ├── index.html             # 录音测试页
    └── run.sh
```

## 3. 环境依赖

按用途安装（无 requirements.txt，自行 pip install）：

| 用途 | 依赖 |
|---|---|
| 导出 | `torch` `transformers` `onnx` `numpy` `onnxruntime` |
| 离线推理 | `numpy` `scipy` `onnxruntime` `transformers` |
| 流式服务 | `fastapi` `uvicorn` `pydantic` `numpy` `scipy` `onnxruntime` |

CUDA 推理装 `onnxruntime-gpu`，`--device cuda` 即可。Windows 下 `python3` 换成 `python`。

## 4. 模型准备

1. **checkpoint 目录**：`Qwen3-ASR-0.6B/`（或 1.7B）。要求 `config.json` 中 `model_type == "qwen3_asr"`，且含 tokenizer / processor 文件。推理只用它做 tokenizer 和特征提取，不加载 torch 权重。
2. **ONNX 目录**：`model/`。权重不入 git，两种获取方式：
   - 自己导出（见下节）；
   - 直接使用已转换的 0.6B ONNX（本仓库 `model/` 下已有）。

## 5. 导出 ONNX

先改 `run.sh` 头部两个路径：

```bash
MODEL_DIR="./Qwen3-ASR-0.6B"        # checkpoint 路径
OUTDIR="./model/model_0.6B"         # ONNX 输出目录
```

然后：

```bash
bash run.sh
```

等价于直接调用：

```bash
python3 export_qwen3_asr_onnx.py \
  --model Qwen3-ASR-0.6B \
  --outdir model/model_0.6B \
  --device cpu \
  --max-total-len 512 \
  --verify
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--model` | 必填 | checkpoint 目录 |
| `--outdir` | 必填 | ONNX 输出目录 |
| `--max-total-len` | 512 | **决定 decoder KV cache 长度上限**。推理时 `prompt+音频 token 数 + max_new_tokens` 必须 ≤ 此值，长音频需调大重新导出 |
| `--opset` | 17 | ONNX opset |
| `--no-int8` | 关 | 跳过 INT8 量化 |
| `--verify` | 关 | 导出后与 PyTorch 输出对照校验 |
| `--fp32-no-external-data` | 关 | FP32 存成单文件（默认外置 `.data`） |
| `--chunk-size` | 100 | conv 前端分块大小，导出与推理必须一致 |

导出完成后 `run.sh` 会自动清理中间产物（`onnx_*`、`thinker.model.*`），输出：

```
conv_frontend.onnx
encoder.onnx / encoder.onnx.data
decoder.onnx / decoder.onnx.data
encoder.int8.onnx / decoder.int8.onnx
```

## 6. 离线推理

### 基本用法

```bash
python3 infer_qwen3_asr.py \
  --model ./Qwen3-ASR-0.6B \
  --conv_frontend ./model/conv_frontend.onnx \
  --encoder ./model/encoder.onnx \
  --decoder ./model/decoder.onnx \
  --wav ./test_wavs/rag_chemistry.wav \
  --device cpu \
  --max-new-tokens 100
```

### 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--model` | 必填 | checkpoint 目录（config.json + tokenizer） |
| `--conv_frontend` / `--encoder` / `--decoder` | 必填 | 三个 ONNX 路径；encoder/decoder 可换 `.int8.onnx` |
| `--wav` | 必填 | 一个或多个 `.wav` / `.npy`；自动混单声道、重采样到 16 kHz |
| `--device` | `cuda` | `cpu` / `cuda` |
| `--max-new-tokens` | 64 | 最大生成 token 数 |
| `--max-total-len` | 1024 | 仅当模型 cache 长度为动态时生效；固定形状以上限以模型为准 |
| `--context` | 无 | 上下文/热词偏置，语义同官方 `transcribe(context=...)`，通过 system prompt 注入 |
| `--chunk-size` | 100 | 需与导出一致 |
| `--debug` | 关 | 打印形状、cache 元信息 |

### 批量

`--wav` 传多个文件即批量推理；多文件时输出前缀为文件名，结尾打印 RTF：

```
[test_wavs/a.wav] 转写文本...
[test_wavs/b.wav] 转写文本...
RTF: 0.0231
```

`--context` 传 1 个值则全部共享，传 N 个则与 N 个 wav 一一对应（context 不同时退化为逐条推理）。

### 精度组合

- FP32：`encoder.onnx` + `decoder.onnx`
- INT8 encoder + FP32 decoder（精度损失最小，推荐先试）
- 全 INT8：`encoder.int8.onnx` + `decoder.int8.onnx`

INT8 模型遇到不支持 `ConvInteger` 算子的 provider（如 CUDA EP）会自动回退到同名 FP32 模型；全 INT8 建议 `--device cpu`。

### decode.sh

`decode.sh` 是演示脚本，内置 FP32 / context 热词 / INT8 / 批量等组合。注意它的路径是作者的导出布局（`./model/model_0.6B/`、`./model/tokenizer`），与本仓库当前布局（ONNX 平铺在 `model/`，checkpoint 在 `Qwen3-ASR-0.6B/`）不同，**使用前需手动改脚本头部的 `Mode` / `MODEL_DIR` / `WAV_PATH` 及 ONNX 路径**。

## 7. 流式实时识别

```bash
bash streaming_qwen3_asr/run.sh
```

环境变量可覆盖：

| 变量 | 默认 | 说明 |
|---|---|---|
| `MODEL_DIR` | `./model/tokenizer` | checkpoint 目录，本仓库请设为 `./Qwen3-ASR-0.6B` |
| `ONNX_DIR` | `./model` | ONNX 目录 |
| `PORT` | 8081 | 服务端口 |
| `DEVICE` | `cpu` | `cpu` / `cuda` |

服务默认加载 INT8 encoder/decoder。启动后浏览器打开 `http://localhost:8081/`，点录音即可实时转写。

### WebSocket 协议

端点：`/api/realtime/ws`

- 客户端 → 服务端：PCM16LE / 16 kHz / 单声道二进制音频帧；结束发文本帧 `{"type": "EOS"}`
- 服务端 → 客户端（JSON）：
  - `TranscriptionResponse`：`{type, text, is_final, segment_id}`（`is_final=false` 为中间结果）
  - `VADEvent`：`{type, is_active}`（仅开启 VAD 时）

### VAD（可选）

`--vad_model` 指定 `silero_vad.onnx` 后按语音段切分输出；文件缺失时警告并回退为无 VAD 连续识别。

## 8. 测试音频

`test_wavs/` 共 24 个样例：中文/方言（湖南/闽南/上海/粤语）、中英文歌曲、远场、噪声、日语、日英混说、越南语、学科名词（rag_*）等。`test_wavs/README.md` 附参考转写文本，可用来对照验证。

## 9. 注意事项

1. **长音频报 `max_total_len not enough`**：`S0 + max_new_tokens` 超过导出时的 `--max-total-len`，调大后重新导出 decoder。
2. **`decode.sh` / `run.sh` 路径需按实际布局修改**（见上文各节说明）。
3. **导出与推理的 `--chunk-size` 必须一致**，否则音频 token 数对不齐（`audio slot mismatch`）。
4. checkpoint 目录的 `config.json` 必须是 `model_type: "qwen3_asr"`，否则 `infer_qwen3_asr.py` 拒绝加载。
5. `model/`、`Qwen3-ASR-0.6B/` 均在 `.gitignore` 中，换机器需重新下载/导出。
